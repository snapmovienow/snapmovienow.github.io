# Formato y recuperación de los verificadores de contraseña

El Worker obtiene la clave de protección del verificador mediante HMAC-SHA256 a partir de `TICKET_SECRET`. El panel de resellers la obtiene de `LINE_CREDENTIAL_KEY` con una etiqueta diferente. Estos secretos ya son necesarios para abrir las copias cifradas del Worker y las credenciales operativas del panel, respectivamente. La protección adicional cubre la copia aislada de los verificadores. La clave principal de cada servicio debe conservarse en su gestor de secretos para poder restaurar una copia independiente de su entorno. El formato conserva las 100 000 iteraciones PBKDF2-SHA256 y la sal individual.

Desplegar el lector compatible antes de activar `PASSWORD_UPGRADE_ENABLED=true`. Con el indicador activo, las altas y los cambios escriben el nuevo formato. Cada acceso correcto convierte el verificador antiguo sin pedir una contraseña nueva. El cambio conserva la versión de acceso, las sesiones y la vigencia. Las cuentas que todavía no hayan entrado pueden conservar el formato previo. Para detener nuevas conversiones se desactiva el indicador manteniendo el lector compatible. Una versión anterior al lector no puede validar los registros convertidos.

Para recuperar el Worker se restablece primero el mismo `TICKET_SECRET` en el gestor de secretos y se verifica la copia con el lector compatible. La restauración contrasta el identificador de clave de cada registro protegido antes de sustituir datos. El mismo principio aplica a D1 y `LINE_CREDENTIAL_KEY` en el panel. Una clave incorrecta o ausente detiene la verificación de registros protegidos. Una rotación futura de cualquiera de las dos claves principales debe conservar lectura con la anterior hasta migrar tanto las credenciales cifradas como los verificadores ligados a ella.
