# SNAPTVNOW catalog maintenance

The production Worker reads `beerus.json` and `movies.json` from the **catalog-feed** branch of `snapmovienow/snapmovienow.github.io`. Updating files on another branch does not request production maintenance. These public files contain titles and public source pages only. Never add passwords, session cookies, tokens, customer information or temporary CDN/HLS signatures.

## Running a review

1. Read this document, both feeds on `catalog-feed`, and `https://api.snaptvnow.com/health`. Confirm `catalog_maintenance.enabled` is true. Use the connected GitHub app, not a browser admin session, for feed updates.
2. For Beerus, inspect the saved series listing and any supported alternative pages for the same series. Preserve existing overrides. The Worker discovers episodes, checks every saved episode and attempts at most **one new episode per feed request**. A missing new episode is a legitimate result; do not substitute a different series. Optional `items` override a specific episode source with `{season, episode_num, page}`.
3. For movies, consult **AMC and Regal Warren** listings for the current review date. The owner wants current cinema releases with no old catalog fillers. Check listing dates; a film detail page or stale cached showtime is not proof of a current screening. Include only released films with an available full film source. Prefer Latino audio and HD; label CAM/subtitles accurately. A trailer, upcoming-release page, similarly named remake or different-year film is not a replacement. Check all selected Gnula movies and seek a replacement page for failures. Preserve IDs and exact names/years when repairing a source. Fewer than 20 films is acceptable when fewer current titles have verified video.
4. Write the relevant feed with a unique `requestId` (8–100 letters, digits, `_`, `-`, `:`) and current UTC ISO `generatedAt`, strictly later than the prior feed. Movies `items` are up to 20 proposals, not a destructive replacement catalog. Each movie needs `{id, name, year, page}`; optional public HTTPS `poster` and `plot`. Use supported stable Gnula pages, not CDN URLs. Supported page hosts are `www2.gnula.one`, `gnula.one`, `www.gnula.one`, and `ww3.gnulahd.nu`. Other providers require a reviewed integration and must not be added as working sources until supported.
5. Create a commit on `catalog-feed` using the current branch head as parent; update the branch with `expected_sha` and no force. On a conflict, reread and preserve the other writer's changes. Modify only the relevant JSON file. No PR/deployment is needed for data updates. Never change application code or security settings as part of a routine review.
6. The existing five-minute server cron consumes the proposal. Read `/health` again until its relevant `requestId` matches the submitted one and `state` is `completed`. Some catalogs need several ticks because checks run in bounded batches. Wait in increments of at most 60 seconds. A submitted feed is **pending**, not a confirmed addition. If the available run cannot wait for completion, explicitly report pending status and check it next run.
7. Report confirmed added/repaired titles and any unresolved errors to the owner in Spanish. For Beerus, report when no new playable chapter is published. Also surface unresolved movie failures from the latest movie report. Do not claim playback on the owner's physical device was tested: the automated check validates upstream playlists, required initial key/map and sampled media bytes through the server's resolver.

## Retention and rotation

The server checks sources with no customer playback connection and stores stable pages. It resolves signed media afresh at playback. Existing metadata, covers and IDs remain intact during source repair. Manual source edits supersede pending jobs.

The limit is **20 visible Gnula movies**, selected from current cinema releases. The owner explicitly authorized removing the old catalog starting October 15, 2026. To withdraw an old film or one no longer in the current cinema selection, include an explicit `retire` array (maximum 20) with `{id,name,year,reason:"outside_current_cinema_selection"}`. Retired IDs must not also appear in `items`. Include `cinemaReview: {checkedAt: "<current UTC ISO timestamp>", sources: ["https://www.amctheatres.com/movies", "<official Regal Warren theatre listing URL>"]}`. The review must be less than eight days old and contain both official AMC and Regal Warren sources. Use current listing evidence, not a missing search result alone. Retirements hide only matching visible Gnula movies, preserve their records and history, revoke obsolete playback leases and respect subsequent manual edits. They run before checks and additions. Do not change series or non-Gnula films.

For a film that still belongs in the current cinema selection but has a broken source, retain it and notify the owner before any later removal if no replacement works. A verified new film may rotate the oldest previously verified visible film at the 20-film cap. If that oldest film is broken or unverified, `rotation_needs_notice` holds the addition. The owner's dated cinema selection withdrawal is separately authorized and does not require filling an empty place with an old film.

Result statuses: `retired` (explicit dated cinema selection withdrawal), `online` (checked), `added`, `repaired`, `unavailable` (retained), `rotation_needs_notice` (held), `catalog_changed` (manual edit won), `already_present`, `catalog_over_limit`. Failed source checks may be temporary; describe them as unavailable at the check time, not proof that the page was permanently removed. Discovery failure is reported separately and does not remove previous episodes.

The public status intentionally omits upstream URLs, credentials and customer data. `runner` reports the latest cron start/completion or a sanitized failure phase. Feed processing and its orchestration use private Durable Object requests; there is no public mutation endpoint. Staging does not process catalog feeds. Both recurring ChatGPT tasks must have working GitHub access before being enabled. If disconnected, report the access issue; never promise that data was changed.

A failed replacement proposal is checked against the original saved source before marking the film unavailable. If the original is online, it is retained with `replacementUnavailable: true`. A user-edited movie title/year prevents automatic source replacement under that identity but does not block health checks for other titles.
